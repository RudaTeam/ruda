# ADR-0014: Моддинг: требования уровня Industrial Craft 2

- **Статус:** Отложено. Механизм модов не выбран, но требования ниже действуют уже сейчас.
- **Дата:** 2026-09-30
- **Срок решения:** до начала вехи M6 (Моддинг)
- **Связанные ADR:** 0003, 0005, 0009, 0011, 0013, 0017

## Контекст

Механизм модов (WASM, Lua, нативные плагины, data-паки) решено выбрать позже. Но цель задана уже сейчас:
**глобальные моды уровня Industrial Craft 2** — машины, энергосети, реакторы, новые руды и деревья,
собственные интерфейсы. Если не заложить это в архитектуру сразу, к моменту выбора механизма движок
окажется закрытым для таких модов.

## Требования к движку (действуют уже сейчас)

Что должен уметь мод уровня IC2 и что для этого нужно в движке:

| # | Мод должен уметь | Движок обеспечивает |
|---|---|---|
| 1 | Добавлять блоки со свойствами: ориентация, активность машины | Реестры и состояния блоков (ADR-0013, 0008) |
| 2 | Добавлять машины с данными и логикой: печь, дробитель, генератор | Block entities с сохраняемыми данными, тиками и синхронизацией с клиентом (ADR-0011) |
| 3 | Хранить в предметах произвольные данные: заряд EU, прочность, режимы | Расширяемые компоненты данных у стака предметов вместо фиксированных полей |
| 4 | Строить сети через много блоков и чанков: энергия, трубы, кабели | События изменения соседей, загрузки и выгрузки чанков; удержание чанков загруженными по «тикетам» с лимитами |
| 5 | Строить мультиблочные структуры | Те же события плюс запросы к миру по областям |
| 6 | Показывать интерфейсы машин: слоты, прогресс, шкала энергии | Серверные меню-контейнеры со слотами и синхронизируемыми свойствами; клиентский экран описывает мод |
| 7 | Задавать свой внешний вид: модели машин, анимации, рендер block entity | Блоки по моделям (ADR-0009), анимированные текстуры, клиентская часть мода |
| 8 | Вмешиваться в генерацию: руды, каучуковые деревья, структуры | Хуки генерации: фичи, структуры, биомы |
| 9 | Добавлять свои типы рецептов: дробитель, компрессор | Расширяемый реестр типов рецептов |
| 10 | Устраивать взрывы реактора, радиацию, урон | Шина событий: взрывы, урон, эффекты сущностей |
| 11 | Давать API другим модам (общая энергосистема) | Зависимости между модами с версиями (semver), порядок загрузки, необязательные зависимости |
| 12 | Отправлять свои сетевые сообщения | Именованные каналы пользовательских пакетов в протоколе |
| 13 | Держать тысячи машин на сервере без лагов | Пакетный API поверх систем ECS вместо вызова мода на каждый блок каждый тик |
| 14 | Обновляться, не портя миры | Версионированные данные модов и миграции при загрузке |

**Ограничения на выбор механизма**, которые уже следуют из других решений:
- **Автозагрузка с сервера** (ADR-0017): всё, что клиент скачивает автоматически, должно работать в песочнице и быть кроссплатформенным. Поэтому нативные плагины на клиенте исключены.
- **iOS** (ADR-0005): JIT запрещён, нужен интерпретатор или AOT-компиляция.
- **Лицензия** (ADR-0003): SDK для моддеров под Apache-2.0, как и движок. Моды могут выходить под любой лицензией.

**Уроки Minecraft 1.7.10, которые не повторяем:**
- конфликты числовых id → строковые id и таблица соответствия в мире (ADR-0013);
- coremod-ы, патчащие байткод → хуков должно хватать, чтобы патчить не требовалось;
- лаги от тикающих машин → пакетная обработка (ADR-0011);
- бесконтрольные чанклоадеры → тикеты с лимитами.

## Кандидаты на оценку

| Критерий | WASM (wasmtime / wasmi) | Lua / Luau | Нативные dylib |
|---|---|---|---|
| Песочница для автозагрузки | ✅ | ✅ (Luau) | ❌ |
| Скорость | близко к нативной (JIT) | ниже, интерпретатор | нативная |
| Один бинарник на все платформы | ✅ | ✅ | ❌ |
| iOS без JIT | интерпретатор (wasmi, Pulley) | ✅ | ❌ |
| Порог входа для моддеров | средний (Rust, C, Zig, AssemblyScript) | низкий | высокий |

Скорее всего, итогом будет гибрид: data-паки для контента и песочница для логики. Но решаем
только после прототипа.

## Как будем решать

На каждом кандидате делаем прототип **«IC2-lite»**: генератор, кабель и машина-потребитель с энергосетью,
GUI машины и сохранением. Меряем производительность на 10 000 машин, удобство API, размер и время загрузки
мода, работу на Raspberry Pi.

## Последствия

- Каждую подсистему, начиная с M1, проектируем с вопросом «как мод это расширит?».
- Пока механизм не выбран, роль мода играет `base` (ADR-0013): на нём проверяем, хватает ли API.
