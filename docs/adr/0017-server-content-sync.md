# ADR-0017: Автозагрузка модов и ресурсов с сервера

- **Статус:** Предложено
- **Дата:** 2026-09-30
- **Связанные ADR:** 0007, 0013, 0014

## Контекст

Чтобы зайти на модовый сервер Minecraft, игрок вручную ставит лаунчер, загрузчик модов и ровно те же
версии модов. Это главный барьер модового мультиплеера. Хотим, чтобы было так: зашёл на сервер — клиент
сам скачал всё нужное.

## Решение

- **Манифест.** При входе сервер отправляет список пакетов: id, версия, хэш BLAKE3, размер, сторона (обе или только сервер), а также ресурс-паки. Хэш всего набора участвует в рукопожатии (ADR-0007).
- **Кэш по содержимому.** Клиент хранит пакеты в `cache/content/<hash>`, поэтому один и тот же мод скачивается один раз для всех серверов. Размер кэша ограничен, старое вытесняется по LRU.
- **Загрузка** идёт через Bulk-поток с низким приоритетом или по HTTPS с CDN, если сервер указал URL. Хэш проверяется всегда.
- **Безопасность.** Автоматически загружается только то, что исполняется в песочнице: данные, ассеты, скрипты в песочнице. Нативный код автоматически не скачивается никогда. Это жёсткое ограничение для ADR-0014.
- **Изоляция сессии.** Скачанный контент попадает в реестры сессии (ADR-0013). При отключении сессия выгружается, и игрок без перезапуска возвращается к своему набору модов.
- **Клиентские моды** (миникарты, шейдеры) выбирает игрок, сервер их не навязывает. Сервер может только запретить известные читерские моды политикой, с оговоркой, что клиент всегда можно подделать.
- **UX.** Прогресс загрузки; для больших загрузок — предупреждение и согласие игрока.

## Последствия

**Плюсы:**
- Модовый мультиплеер без лаунчеров и ручной установки.
- Общий кэш экономит трафик и место на диске.

**Минусы и риски:**
- Требование песочницы сужает выбор механизма модов.
- Загружать и выгружать контент без перезапуска сложно для рендера (текстуры, модели) и звука.
- Вредоносный контент даже в песочнице может съедать CPU и память, поэтому модам нужны лимиты ресурсов.
