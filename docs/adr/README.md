# Архитектурные решения (ADR)

Здесь записаны архитектурные решения проекта: что решили, почему и какой ценой.
Формат — упрощённый [MADR](https://adr.github.io/madr/) на русском, шаблон — [`template.md`](template.md).
Порядок работы — в [ADR-0001](0001-record-architecture-decisions.md).

## Статусы

| Статус | Значение |
|---|---|
| **Предложено** | Черновик, ждёт подтверждения. Можно прототипировать, но нельзя строить на нём необратимое. |
| **Принято** | Действующее решение. По существу не редактируется, меняется только новым ADR. |
| **Отложено** | Решение сознательно отложено. ADR фиксирует требования и срок, к которому нужно решить. |
| **Отклонено** | Вариант рассмотрен и отвергнут. Хранится, чтобы не обсуждать повторно. |
| **Заменено ADR-NNNN** | Решение больше не действует, см. новый ADR. |

## Бэклог решений

Эти решения понадобятся, но ещё не оформлены:

- UI-фреймворк (ограничения — в ADR-0019)
- Аудио
- Генерация мира: алгоритмы, шумы, биомы (требование из ADR-0016 — дешёвая грубая выборка поверхности)
- Модель движения и физика игрока: детали предсказания и согласования (ADR-0006) — до вехи M2
- Аккаунты и аутентификация игроков (ADR-0007) — до вехи M2
- Формат data-файлов контента (вместе с ADR-0014)
- Локализация
- Дистрибуция и обновления: Steam, свой лаунчер
- Краш-репорты и телеметрия
