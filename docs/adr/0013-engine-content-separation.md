# ADR-0013: Движок без контента: реестры и базовая игра отдельным пакетом

- **Статус:** Предложено
- **Дата:** 2026-09-30
- **Связанные ADR:** 0002, 0008, 0010, 0014, 0015, 0017

## Контекст

Цель — моды уровня Industrial Craft 2 (ADR-0014). Minecraft эпохи 1.7.10 показал, что бывает, если игру
не задумывали как платформу: конфликты числовых id, coremod-ы, которые патчат байткод, хрупкая
совместимость модов. Самый надёжный способ получить достаточный мод-API — написать на нём саму игру.

## Решение

**Движок не знает игрового контента.** В нём есть только служебные блоки `air` и `unknown` (ADR-0010).
Блоки, предметы, типы сущностей, биомы, рецепты, звуки и типы меню регистрируются в **реестрах**.

- **Идентификаторы** имеют вид `namespace:path` (`base:stone`, `ic2:macerator`). Числовые id назначаются при заморозке реестров, сохраняются в мире (новые дописываются в конец) и передаются клиенту при входе. В API числовых id нет.
- **Жизненный цикл:** регистрация (движок → base → моды в порядке зависимостей) → заморозка → игра. После заморозки реестры не меняются.
- **Реестры — не глобальные `static`.** Они принадлежат игровой сессии. Когда клиент заходит на сервер с другим набором модов, он строит новый набор реестров, а не перезапускается (ADR-0017).
- **Теги** (`base:logs`, `base:mineable/pickaxe`) — именованные группы, через которые моды взаимодействуют, не ссылаясь друг на друга напрямую.
- **Тексты** — ключи локализации, а не строки в коде.

**Базовая игра — пакет `content/base`**, который зависит только от публичного API движка. Граница
крейта не даёт ему использовать внутренности движка. Когда появится система модов (ADR-0014), `base`
станет первым и самым большим модом. Если base что-то нужно, а API этого не позволяет, расширяем API,
а не делаем исключение.

**Данные вместо кода, где возможно:** свойства блоков, модели, рецепты, лут и параметры генерации
описываются данными. Формат data-файлов выберем вместе с ADR-0014. До тех пор base объявляет контент
Rust-кодом через тот же API реестров.

## Последствия

**Плюсы:**
- Мод-API заведомо достаточен: на нём написана вся игра.
- Моды не конфликтуют по id, а миры переживают изменение состава модов.

**Минусы и риски:**
- Старт медленнее: всё идёт через реестры, даже то, что проще было бы захардкодить.
- Нужна дисциплина: желание «быстро добавить в движок» останавливаем на ревью.
