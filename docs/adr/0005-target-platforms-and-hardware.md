# ADR-0005: Целевые платформы и минимальные требования

- **Статус:** Принято
- **Дата:** 2026-09-30
- **Связанные ADR:** 0002, 0004, 0009, 0014, 0016, 0019

## Контекст

Требования: полная поддержка Windows, macOS и Linux, работа «даже на калькуляторе», мобильные
платформы — позже. «Калькулятор» нужно превратить в конкретное железо и измеримые цифры,
иначе оптимизация станет вечной и бесцельной.

## Решение

### Платформы

| Платформа | Архитектура | Уровень | Графический API |
|---|---|---|---|
| Windows 10/11 | x86_64 | 1 | DX12 / Vulkan → GL |
| macOS 11+ | aarch64, x86_64 | 1 | Metal |
| Linux (X11 и Wayland) | x86_64 | 1 | Vulkan → GL |
| Linux ARM (Raspberry Pi OS 64-bit и др.) | aarch64 | 1 — эталон «калькулятора» | Vulkan → GLES 3.1 |
| Windows on ARM | aarch64 | 2 | DX12 / Vulkan |
| Android | aarch64 | 3 — позже | Vulkan / GLES 3 |
| iOS / iPadOS | aarch64 | 3 — позже | Metal |
| Web | wasm32 | не планируется | — |

- **Уровень 1** — сборка и тесты в CI на каждый PR, релизные сборки.
- **Уровень 2** — сборка в CI, тестирование по возможности.
- **Уровень 3** — сборок пока нет, но архитектура не должна им мешать.

Поддерживаем только 64-битные платформы. Linux-сборки линкуем против старого glibc
(например, через `cargo-zigbuild`), чтобы они запускались на большинстве дистрибутивов.
Steam Deck — обычный Linux x86_64.

### Эталонные стенды

Цифры — это цели, по которым принимаем работу. Уточним их по первым бенчмаркам.

| Стенд | Железо | Цель |
|---|---|---|
| **«Калькулятор»** | Raspberry Pi 4 Model B (4 ГБ) или x86-ПК: 2 ядра + Intel HD 4000, 4 ГБ ОЗУ | ≥ 30 FPS, полные чанки на 64 блока (дальше — LOD, ADR-0016); одиночная игра целиком ≤ 1 ГБ ОЗУ |
| **Средний ПК** | 4–6 ядер, GTX 1060 / RX 580, 8 ГБ ОЗУ | ≥ 144 FPS при дальности 256 блоков |
| **Сервер** | Raspberry Pi 4 (4 ГБ) | 10 игроков при стабильных 20 TPS |

Производительность меряем автоматически. Бенчмарк-сценарий с фиксированным сидом и заскриптованным
пролётом камеры собирает перцентили времени кадра (p50/p99), потребление памяти и время тика.
Сценарий регулярно запускается на стенде Raspberry Pi (self-hosted runner). Регрессия блокирует релиз.

### Что мобильные платформы требуют уже сейчас

Чтобы порт на мобильные не превратился в переписывание:
- рендер переживает потерю и пересоздание поверхности (ADR-0004);
- пути к данным получаем через платформенную абстракцию, без хардкода;
- ввод абстрагирован до действий, а сенсорный ввод — просто ещё одно устройство (ADR-0019);
- нет зависимости от JIT и динамической загрузки нативных библиотек: на iOS их нет (важно для ADR-0014);
- игра переживает сворачивание и выгрузку из памяти: прогресс сохраняется регулярно.

## Последствия

**Плюсы:**
- «Калькулятор» стал измеримым: есть железо, цифры и автоматическая проверка.
- Мобильные платформы не потребуют переписывать архитектуру.

**Минусы и риски:**
- Нужен физический стенд Raspberry Pi и self-hosted runner.
- Матрица CI из четырёх и более целей увеличивает время и стоимость проверок.
- Wayland, HiDPI и драйверы Linux потребуют отдельного внимания.
